# Семестровая работа № 1 по ОРИС

**Проект:** Semestrovaya_1
**Тема:** каталог коллекционных карт Riftbound

## 1. Описание проекта

Веб-каталог коллекционных карт Riftbound.

Основные возможности:

- просмотр галереи карт с поиском, фильтрацией и сортировкой;
- просмотр подробной информации о карте Серафины (AJAX, без перезагрузки страницы);
- вход в административную панель;
- управление контентом через административный интерфейс:
  карточки, наборы, домены, типы карточек, теги;
- редактирование текста способности карточки
  в WYSIWYG-редакторе Quill.

Данные хранятся в PostgreSQL.

Веб-сервер реализован самостоятельно на основе HttpListener
и обрабатывает запросы параллельно.
ASP.NET Core для обработки HTTP-запросов не используется.

Приложение поддерживает три способа запуска:

- через Docker Compose (приложение и база в контейнерах,
  рекомендуемый способ);
- через Docker (только приложение, база на компьютере);
- обычный запуск средствами .NET.

## 2. Технологии и структура

Используемые технологии:

- C#, .NET 9;
- HttpListener;
- PostgreSQL, Npgsql;
- HTML, CSS и JavaScript;
- Quill — единственная JS-библиотека,
  используется как WYSIWYG-редактор в админке;
- MSTest;
- Docker, Docker Compose.

Основные части приложения:

- `Program.cs` — настройка приложения, запуск HTTP-сервера
  и параллельная обработка запросов;
- `Controllers` — обработка запросов к страницам и админке;
- `Server` — маршрутизация запросов и безопасное разрешение
  путей к статическим файлам;
- `Models` — модели данных;
- `Orm` — собственная ORM (атрибуты, карта модели,
  кэш карт `EntityMapCache`, универсальный репозиторий)
  и обёртка доступа к базе (`Database`);
- `Repositories` — запросы данных для галереи,
  деталей карточки и связей карточек;
- `Data` — проверка CRUD-операций ORM на живой базе
  (`OrmCrudProbe`, режим `--check-orm`);
- `Security` — аутентификация администратора:
  хэширование пароля (PBKDF2), сессии, CSRF-токены;
- `Templating` — собственный шаблонизатор
  (`TemplateEngine`, `TemplateModel`);
- `Views` — HTML-шаблоны;
- `Sql` — SQL-скрипты создания и наполнения базы данных;
- `Static` — стили, JavaScript, изображения и шрифты;
  сторонняя библиотека Quill лежит в `Static/lib/quill`.

Изображения и шрифты скачиваются скриптом
`Download-Assets.ps1` по манифесту `assets.json`
и хранятся локально в `Static`.

`Semestrovaya_1.Tests` — отдельный проект автоматических тестов.

## 3. Быстрый запуск через Docker Compose

Рекомендуемый способ: поднимаются и приложение, и PostgreSQL.
База `oris_riftbound` создаётся и наполняется SQL-скриптами
проекта автоматически при первом запуске.

Требования:

- установленный и запущенный Docker Desktop;
- режим Linux-контейнеров;
- работающая подсистема WSL 2 при использовании Windows.

Шаги:

1. В папке с `docker-compose.yml` создать файл `.env`:

```javascript
POSTGRES_PASSWORD=CHANGE_ME_DB_PASSWORD
ORIS_ADMIN_USERNAME=admin
ORIS_ADMIN_PASSWORD=CHANGE_ME_ADMIN_PASSWORD
```

`POSTGRES_PASSWORD` — пароль, который будет назначен
пользователю `postgres` внутри контейнера базы.
Пароль администратора должен соответствовать требованиям
из раздела 5.

2. Выполнить:

```javascript
docker compose up --build
```

3. Дождаться в журнале строки
   `Подключение к БД успешно: oris_riftbound`.
4. Открыть:

```javascript
http://localhost:8080/
```

Остановка: Ctrl+C, затем `docker compose down`.

Данные базы хранятся в volume `db-data` и сохраняются
между перезапусками. SQL-скрипты выполняются только
при первом создании базы. Чтобы пересоздать базу с нуля:

```javascript
docker compose down -v
docker compose up --build
```

Внимание: `down -v` удаляет все данные контейнерной базы.

Контейнерная база никак не связана с PostgreSQL,
установленным на компьютере, и не конфликтует с ним:
порт 5432 наружу не публикуется.

## 4. Запуск через Docker с внешней базой

Альтернативный вариант: контейнер запускает только
приложение, PostgreSQL работает на компьютере.

База `oris_riftbound` должна быть создана и наполнена
по разделу 6.

Файл `.env` рядом с Dockerfile:

```javascript
ORIS_DB_CONNECTION=Host=host.docker.internal;Port=5432;Database=oris_riftbound;Username=postgres;Password=CHANGE_ME
ORIS_ADMIN_USERNAME=admin
ORIS_ADMIN_PASSWORD=CHANGE_ME_ADMIN_PASSWORD
ORIS_HTTP_PREFIX=http://+:8080/
```

`host.docker.internal` используется для подключения
из контейнера к PostgreSQL на компьютере.

Сборка образа:

```javascript
docker build -t oris-app .
```

Запуск контейнера:

```javascript
docker run --rm --name oris-app --env-file .env -p 127.0.0.1:8080:8080 oris-app
```

Остановка: Ctrl+C или `docker stop oris-app`
из другого терминала.

Настоящий файл `.env` с паролями не должен попадать
в Git-репозиторий или в Docker-образ.
Он исключается через `.gitignore` и `.dockerignore`.

## 5. Переменные окружения

При обычном запуске через `dotnet run` задаются:

- `ORIS_DB_CONNECTION` — строка подключения к PostgreSQL;
- `ORIS_ADMIN_USERNAME` — логин администратора;
- `ORIS_ADMIN_PASSWORD` — пароль администратора.

Дополнительная переменная:

- `ORIS_HTTP_PREFIX` — HTTP-префикс HttpListener.
  Если не задана, используется `http://localhost:8080/`.

При запуске через Docker Compose в `.env` задаются
`POSTGRES_PASSWORD`, `ORIS_ADMIN_USERNAME`,
`ORIS_ADMIN_PASSWORD`; строку подключения и префикс
compose подставляет сам.

Требования к данным администратора:

- логин не пустой, не более 100 символов,
  без пробелов в начале и конце;
- пароль — от 12 до 200 символов.

Пример строки подключения для обычного запуска:

```javascript
Host=127.0.0.1;Port=5432;Database=oris_riftbound;Username=postgres;Password=CHANGE_ME
```

## 6. Подготовка базы данных вручную

Нужно только для обычного запуска и запуска
через Docker с внешней базой. Docker Compose
выполняет эти шаги сам.

Приложение ожидает базу данных с точным именем:

```javascript
oris_riftbound
```

Подготовка новой базы:

1. Подключиться к PostgreSQL через pgAdmin
   или другой SQL-клиент.
2. Выполнить отдельно:

```sql
CREATE DATABASE oris_riftbound;
```

3. Переключить подключение на `oris_riftbound`.
4. Выполнить SQL-скрипты проекта в порядке
   возрастания номера:

```javascript
001_create_tables.sql
002_seed_domains.sql
003_seed_initial_cards.sql
004_seed_gallery_cards.sql
005_add_is_new.sql
006_fill_card_details.sql
```

При старте приложение проверяет подключение и имя базы.
Если подключиться не удалось или имя базы отличается,
приложение выводит сообщение и завершает работу.

## 7. Обычный запуск через Rider

1. Открыть решение проекта в Rider.
2. Открыть Run → Edit Configurations…
3. Выбрать конфигурацию запуска основного приложения.
4. В поле Environment variables задать
   `ORIS_DB_CONNECTION`, `ORIS_ADMIN_USERNAME`,
   `ORIS_ADMIN_PASSWORD`.
5. Убедиться, что PostgreSQL запущен, а база подготовлена
   по разделу 6.
6. Запустить приложение кнопкой Run.
7. Открыть `http://localhost:8080/`.

## 8. Обычный запуск из PowerShell

Открыть терминал в папке основного проекта,
где находится файл `.csproj`.

Задать переменные окружения для текущего терминала:

```powershell
$env:ORIS_DB_CONNECTION = 'Host=127.0.0.1;Port=5432;Database=oris_riftbound;Username=postgres;Password=CHANGE_ME'
$env:ORIS_ADMIN_USERNAME = 'admin'
$env:ORIS_ADMIN_PASSWORD = 'CHANGE_ME_ADMIN_PASSWORD'
```

Выполнить:

```javascript
dotnet run
```

Открыть `http://localhost:8080/`.
Остановка — Ctrl+C в терминале.

Важно: файл `.env` командой `dotnet run`
автоматически не загружается.

## 9. Работа с сайтом

Основные адреса:

- `http://localhost:8080/` — галерея карт;
- `http://localhost:8080/cards/seraphine` — подробная
  информация о карте Серафины (используется
  для AJAX-запроса из галереи);
- `http://localhost:8080/admin` — административный раздел.

В галерее доступны поиск, фильтры по наборам
и новым картам, сортировка.

Для доступа к административному разделу используются
значения `ORIS_ADMIN_USERNAME` и `ORIS_ADMIN_PASSWORD`.
Сессии хранятся в памяти сервера и сбрасываются
при его перезапуске.

Для публичных страниц и статических ресурсов
предусмотрены методы GET и HEAD.
Неподдерживаемые методы отклоняются с кодом 405.
Неизвестный маршрут или отсутствующий статический файл
обрабатываются ответом 404.

## 10. Шаблонизатор

В проекте используется собственный шаблонизатор.

Поддерживаемые возможности:

- подстановка переменных с HTML-экранированием;
- подстановка доверенного HTML без экранирования;
- циклы по коллекциям;
- условные блоки с веткой else и без неё;
- единый метод `RenderPage`, который применяет
  условия, циклы и переменные за один вызов
  и проверяет, что все блоки шаблона обработаны.

Пример переменной:

```javascript
{{Name}}
```

Пример вставки доверенного HTML (только для данных,
которые вводит администратор):

```javascript
{{{Ability}}}
```

Пример цикла:

```javascript
{{#each Cards}}
<p>{{Name}}</p>
{{/each}}
```

Пример условия:

```javascript
{{#if HasCards}}
Есть карточки
{{else}}
Карточек нет
{{/if}}
```

Данные для страницы собираются в `TemplateModel`:
`Values`, `Conditions`, `Collections`.

HTML-шаблоны находятся в `Views` и копируются
при сборке и публикации приложения.

## 11. Автоматические тесты

Тесты находятся в проекте `Semestrovaya_1.Tests`.
Используется MSTest.

Основные группы тестов:

- EntityMapTests — сопоставление моделей и таблиц,
  первичный ключ, столбцы вставки и обновления,
  кэш карт, отклонение некорректных описаний моделей;
- RequestRouterTests — маршруты публичных страниц,
  статических ресурсов и админки, обработка
  HTTP-методов, неизвестные пути;
- StaticFileResolverTests — разрешение корректных путей,
  декодирование URL, защита от выхода
  за пределы каталога Static;
- TemplateEngineTests — переменные, экранирование,
  вставка доверенного HTML, циклы, условия,
  единый рендеринг страницы, ошибочные шаблоны.

Запуск через Rider: правый клик по `Semestrovaya_1.Tests`
→ Run Unit Tests.

Запуск из терминала в папке тестового проекта:

```javascript
dotnet test
```

Актуальное количество тестовых случаев
отображается в результатах запуска.

Тесты EntityMap проверяют сопоставление моделей и таблиц.
Они не заменяют отдельную проверку CRUD-операций
с настоящей базой данных (раздел 12).

## 12. Проверка ORM с базой данных

Приложение поддерживает режим `--check-orm`:

```javascript
dotnet run -- --check-orm
```

Вызывается `OrmCrudProbe`: для каждой сущности
проверяются создание, чтение, обновление и удаление
записи через собственную ORM. После завершения проверки
приложение выходит, не запуская HTTP-сервер.

Проверку следует выполнять на учебной или тестовой базе,
а не на базе с важными данными.

При обработанной ошибке ORM-проверки приложение
устанавливает ненулевой код завершения.

## 13. Возможные проблемы

**«Не задана переменная ORIS_DB_CONNECTION».**
Строка подключения не передана приложению.
Проверьте переменные окружения Rider, PowerShell
или файл `.env` при запуске через Docker
с внешней базой.

**«Не удалось подключиться к БД».**
Проверьте, что PostgreSQL запущен, база `oris_riftbound`
существует и наполнена, пользователь, пароль и порт верны.
Для запуска через Docker с внешней базой используется
`host.docker.internal`; для Docker Compose строка
подключения собирается автоматически.

**Сообщение о некорректных данных администратора.**
Проверьте `ORIS_ADMIN_USERNAME` и `ORIS_ADMIN_PASSWORD`:
нет ли пробелов по краям логина,
соответствует ли длина значений требованиям.

**Ошибка Docker: «failed to read dockerfile».**
Команда запущена не из той папки.
Перейдите в папку с Dockerfile и `.csproj`.

**Ошибка «no configuration file provided».**
Команда `docker compose` запущена не из папки
с файлом `docker-compose.yml`. Перейдите в эту папку
или укажите файл явно:
`docker compose -f Semestrovaya_1/docker-compose.yml up --build`.

**В журнале строка «Сервер запущен: http://+:8080/».**
Это нормально при запуске в Docker: `+` означает,
что приложение слушает все сетевые интерфейсы контейнера.
По этому адресу переходить не нужно —
в браузере открывайте `http://localhost:8080/`.

**База в Docker Compose пустая или без изменений.**
SQL-скрипты выполняются только при первом создании
volume. Пересоздайте базу: `docker compose down -v`,
затем `docker compose up --build`.

**Ошибка о занятом порте 8080.**
Остановите предыдущий экземпляр приложения
или контейнер, использующий этот порт.

**Изменения исходников не появились в Docker.**
Пересоберите: `docker compose up --build`
(или `docker build` + `docker run` для ручного варианта).

## 14. Безопасность настроек

Не публиковать:

- настоящие пароли PostgreSQL;
- пароль администратора;
- локальный файл `.env`;
- строки подключения с действующими паролями.

В документации используются только примерные значения.
